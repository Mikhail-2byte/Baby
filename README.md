# Baby Bot

Семейный Telegram-бот для первого года жизни ребёнка: трекер кормлений, сна,
подгузников и веса; напоминания, которые переживают спящий компьютер;
статистика за сутки, неделю и месяц.

Работает в **групповом чате** — записи общие, и оба родителя видят одно и то же.
В личке бот отвечает отказом: там семьи нет.

---

## Что нужно один раз

### 1. Бот у BotFather

1. `/newbot` → имя и username.
2. **Обязательно** выключить приватность, иначе бот не увидит в группе ничего,
   кроме команд, и ответ числом на «сколько мл?» до него не дойдёт:
   `/mybots` → выбрать бота → Bot Settings → Group Privacy → **Turn off**.
3. Токен положить в `.env` в `BOT_TOKEN=`.

Токен **обязательно отдельный** от Family_planer. Два long polling на одном
токене не падают и не ругаются — они молча делят апдейты между собой, и часть
записей о кормлении просто исчезает.

### 2. Окружение

```cmd
cd C:\Projeck\Baby
python -m venv .venv
.venv\Scripts\pip install -r requirements-dev.txt
copy .env.example .env
```

Дальше заполнить `.env` — он написан как документация, там объяснено каждое
значение.

### 3. Чат

Создать группу с женой, добавить бота, дать ему права администратора
(нужны только для закрепления панели — без них бот работает, панель просто
не закрепляется). Написать в чат любое сообщение: семья заведётся сама,
команды `/start` не требуется.

Затем `/baby` — мастер спросит имя, пол, момент рождения и вес при рождении.

### 4. Таблицы роста ВОЗ

```cmd
.venv\Scripts\python kb\load_who.py
```

Скачивает шесть таблиц стандартов роста, кладёт коэффициенты L, M, S в базу и
**сверяет нашу формулу с готовыми значениями ВОЗ на всех контрольных точках**
(около 78 тысяч). Без этого бот работает, но показывает вес без центилей — в
первые дни этого и достаточно, там важнее потеря массы от рождения.

Файлы остаются в `kb/raw/who/`, повторный запуск сети не требует
(`--offline` запрещает её вовсе).

### 5. База знаний

```cmd
.venv\Scripts\python kb\build_kb.py
.venv\Scripts\python kb\eval_kb.py
```

Первая команда скачивает документы из `kb/sources.yaml`, разбирает их и
складывает `data/kb.db`. Вторая показывает, насколько хорошо по ней ищется, —
её стоит запускать после каждой правки источников.

Без этого бот работает как раньше, просто не отвечает на вопросы.

**Пересобирать при остановленном боте.** Windows не даст подменить файл,
открытый чужим процессом.

Один документ из списка — рекомендация AAP о безопасном сне — скачивается
руками: издательство отдаёт 403 всему, что не браузер. Сборщик скажет, куда
положить файл. Без него база собирается, просто без раздела о безопасном сне.

`kb/raw/` и `kb/normalized/` в git не попадают. Второй каталог стоит открыть
хотя бы раз: там лежит текст ровно в том виде, в каком его читает бот, и
сравнить его с исходным PDF — единственный способ заметить, что разбор съехал.

## Запуск

### Разово, чтобы посмотреть

```cmd
run.cmd
```

Скрипт накатывает миграции и запускает бота. Останавливается по Ctrl+C.

### Постоянно, с автозапуском

Схема унаследована от Family_planer и проверена на этой машине:

```
Планировщик задач → wscript.exe → C:\Projeck\_quiet\run-baby-hidden.vbs
                                 → cmd /c run.cmd
                                 → alembic upgrade head → python -m bot
```

Зарегистрировать задачу:

```powershell
Register-ScheduledTask -Xml (Get-Content "C:\Projeck\Baby\docs\BabyBot.task.xml" -Raw) -TaskName "BabyBot"
```

Что важно в этой задаче и почему:

| Параметр | Значение | Зачем |
|---|---|---|
| Триггер 1 | При входе в систему, задержка 1 мин | Karing — приложение пользовательской сессии. Задача «вне зависимости от регистрации пользователя» попала бы в сессию 0, где пользовательского прокси не существует, и бот молча крутился бы в рестартах |
| Триггер 2 | Ежедневно с 00:02, повтор каждые 5 мин | Сторож: поднимает бота, если тот умер |
| MultipleInstances | IgnoreNew | Сторож не должен плодить вторые экземпляры |
| ExecutionTimeLimit | PT0S | Без лимита — бот работает сутками |
| Запуск через `wscript` | окно скрыто | Видимое окно `cmd.exe` можно закрыть, и бот умрёт с кодом `0xC000013A`, который «Перезапуск при сбое» не ловит |
| Третий аргумент `Run` = True | ждать завершения | Иначе wscript выйдет сразу, задача сочтёт себя выполненной, и `IgnoreNew` перестанет защищать |

Второй рубеж — **замок ОС внутри процесса** (`bot/services/lock.py`): он ловит
запуск двойным щелчком, из другой сессии и мимо задачи.

## Windows: без этого «24/7» не получится

```cmd
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change disk-timeout-ac 0
```

**Скрытая настройка, которую не показывает `powercfg /query`** — «сон после
автоматического пробуждения», по умолчанию 120 секунд. Машина просыпается по
таймеру и через две минуты засыпает обратно:

```cmd
powercfg -attributes SUB_SLEEP 7bc4a2f9-d8fc-4469-b07b-33eb785aaca0 -ATTRIB_HIDE
powercfg /setacvalueindex SCHEME_CURRENT SUB_SLEEP 7bc4a2f9-d8fc-4469-b07b-33eb785aaca0 0
powercfg /setactive SCHEME_CURRENT
```

Ещё:

- отключить **быстрый запуск** (он ломает корректный старт служб после «выключения»);
- отложить автоперезагрузки Windows Update;
- в Диспетчере устройств запретить отключение сетевого адаптера для экономии энергии;
- добавить процесс в «неприкасаемые» в `C:\Projeck\_quiet\quiet-mode.ps1`,
  иначе тихий режим закроет его через час простоя.

Во сне S3 бот **не теряет сообщения**: процесс замирает, но не перезапускается,
`drop_pending_updates` не срабатывает, а Telegram держит апдейты до 24 часов.
Теряет — рестарт.

## Прокси

`api.telegram.org` из России не открывается: с весны 2026 это блокировка, а не
замедление. Настройки прокси — по одной на канал (`TELEGRAM_PROXY`,
`OPENROUTER_PROXY`, `GROQ_PROXY`, `STT_PROXY`), формат
`http://user:pass@host:port`, пусто = напрямую.

Порт `127.0.0.1:3067` — тот же Karing, что обслуживает Family_planer.
Он нестабилен: в живом логе планировщика сотни `ProxyConnectionError` за сутки.
Aiogram переподключается сам, но логи от этого растут, поэтому
`aiogram.dispatcher` здесь приглушён до WARNING.

## Данные и бэкапы

Всё в `data/baby.db` (SQLite, WAL). Снимки — `data/backups/baby-ГГГГ-ММ-ДД.db`,
две недели, снимаются раз в сутки через `VACUUM INTO` (а не копированием файла:
при WAL копия может оказаться битой).

`/backup` присылает копию файлом прямо в чат. Пользуйтесь: **вес и кормления за
первый год невосстановимы**, а диск домашнего ПК один. Telegram здесь работает
бесплатным офсайт-хранилищем.

Восстановление: остановить бота, положить файл из `backups/` на место
`data/baby.db`, удалить `baby.db-wal` и `baby.db-shm`, запустить.

## Разработка

```cmd
.venv\Scripts\python -m pytest -q
.venv\Scripts\python -m ruff check bot tests kb
.venv\Scripts\python -m mypy
.venv\Scripts\python kb\eval_kb.py
```

Последняя — не тест, а замер: поиск по базе знаний оценивается на наборе из
`kb/eval.yaml`. Правя поиск, сравнивайте числа до и после; правя источники —
тоже.

После правки `bot/db/models.py` **обязательно**:

```cmd
.venv\Scripts\alembic revision --autogenerate -m "описание"
```

Иначе `tests/test_migrations.py` покраснеет — он для того и заведён.
Чинить его правкой сравнения нельзя.

Устройство проекта и список инвариантов — в `CLAUDE.md`.
Прогресс по этапам — в `docs/TASKS.md`.

## Команды

| Команда | Что делает |
|---|---|
| `/panel` | выпустить панель заново (она уедет вниз чата) |
| `/today`, `/week` | сводки; период переключается кнопками |
| `/chart` | графики: вес с коридорами ВОЗ и ритм суток |
| `/export` | выгрузка для педиатра: CSV и PDF |
| `/stage` | что происходит на этой неделе: развитие, занятия, вехи |
| `/remind` | напоминания: кормление, витамин D, взвешивание; календарь прививок и осмотров с датами от дня рождения. Всё выключено, пока не включите |
| `/redflags` | список тревожных признаков — прочитать спокойно, заранее |
| `/weight`, `/weight 3560` | записать вес |
| `/baby` | карточка ребёнка или мастер её создания |
| `/backup` | копия базы файлом в чат |
| `/ping` | проверка живости; отвечает временем бота |
| `/cancel` | отменить текущий ввод |

Команды для вопросов нет намеренно: на панели есть кнопка **«❓ Вопрос»**.
Тап — и следующее сообщение уходит в поиск по базе знаний. Ответ приходит
вместе с цитатой из документа и ссылкой на него; не нашлось — бот так и
скажет, а не станет сочинять.

## Содержание

Два файла, в которых живёт всё, что бот говорит по существу:

| Файл | Что внутри |
|---|---|
| `bot/content/redflags.yaml` | тревожные признаки, пороги, что делать, источники |
| `bot/content/weeks.yaml` | развитие по периодам, вехи CDC, моторные окна ВОЗ |
| `bot/content/schedule_ru.yaml` | календарь прививок и осмотров, тексты и дозы напоминаний |
| `bot/content/qa_prompt.md` | инструкция модели: только по фрагментам, без своих чисел |
| `kb/sources.yaml` | документы базы знаний: тир, лицензия, откуда скачивать |

Все сделаны данными, а не кодом, ровно затем, чтобы их мог прочитать и
поправить человек без программирования — в идеале знакомый врач. В Python нет
ни одного симптома, ни одного порога и ни одной фразы про развитие.

Источники базы знаний на сегодня: клинические рекомендации Минздрава «Здоровый
новорождённый» и «Неонатальная желтуха» (2025), приказы 211н о профилактических
осмотрах и 1122н о календаре прививок, Программа оптимизации вскармливания
детей первого года жизни (Союз педиатров России), руководство ВОЗ по сну и
активности детей до 5 лет. Ничего «с сайта про детей»: у каждого документа
есть автор, которого можно назвать вслух, и лицензия, записанная рядом.

**Ничего из этого не генерируется нейросетью и не будет.** Самые читаемые
сообщения бота приходят сами и читаются как «так и должно быть»; сочинённый
текст ошибётся здесь один раз, и доверия к остальному уже не будет.

## Оговорка

Бот не врач и не ставит диагнозов.

Он умеет заметить в сообщении то, что в клинических рекомендациях названо
поводом для осмотра, и напомнить об этом правиле — фиксированным текстом,
без участия нейросети. Список признаков и пороги лежат в
`bot/content/redflags.yaml`, источники указаны там же: NICE NG143, WHO IMCI,
клинические рекомендации МЗ РФ. Прочитать весь список заранее — `/redflags`.

**Молчание бота ничего не значит.** Он ищет признаки, названные словами, а не
оценивает состояние ребёнка. При любом сомнении — **103**, а не бот.

На вопросы он отвечает только по документам из `kb/sources.yaml` и всегда
показывает, откуда взял. Нейросеть в этом пути участвует ровно одним способом:
пересказывает найденное короче. Она не решает, что искать, не добавляет от
себя и не пишет чисел, которых нет в источнике, — последнее проверяется кодом,
а не обещанием в промпте. Без ключей бот просто покажет найденные фрагменты.
